# URL을 Markdown으로 바꿔 LLM에 넘기기

웹 페이지 URL을 붙여넣으면 본문만 Markdown으로 뽑아 보여 주고, 복사·다운로드하거나 프롬프트를 붙여 ChatGPT·Claude 새 채팅으로 바로 넘길 수 있게 합니다.

## 연결된 자료

- [prototype.html](prototype.html) — 승인된 화면입니다. 화면 구성, 상태별 모습, 문구, 하단 고정 내보내기 바의 배치와 동작, 시각 스타일을 이 파일이 정합니다.
- [visual-direction](../../decisions/visual-direction.md) — 서비스 전체의 시각 방향(보노보노 PPT풍)과 그 경계를 정합니다.
- [ui-composition](../../decisions/ui-composition.md) — shadcn 구성, semantic token, 상태 설계 원칙을 정합니다.
- [dependency-versions](../../decisions/dependency-versions.md) — 새 의존성을 추가할 때의 버전 기준을 정합니다.

## 사용자가 얻는 것

- 공개 웹 페이지의 URL 하나로 광고·메뉴 없는 본문 Markdown을 얻습니다.
- 결과를 바로 읽어 보고, 복사하거나 `.md` 파일로 내려받습니다.
- 프롬프트(프리셋 또는 직접 입력)를 골라 본문과 함께 ChatGPT나 Claude 새 채팅으로 넘깁니다.
- 밝은 테마와 어두운 테마 중 원하는 쪽으로 봅니다.

## 범위

한 화면짜리 서비스이며, 템플릿의 기본 홈 화면을 이 화면으로 바꿉니다.

1. **입력**: URL 입력창, 입력창 안의 지우기 버튼, 변환 버튼
2. **변환**: 페이지를 가져와 defuddle로 본문과 메타데이터(제목, 저자, 사이트명)를 Markdown으로 추출
3. **결과 확인**: 사이트명·URL·글자 수, 제목, 저자로 된 헤더와 렌더링된 Markdown 본문
4. **내보내기**: 결과 아래에 붙는 하단 고정 바
   - 복사하기, `.md` 다운로드
   - 프롬프트 선택: 프리셋 "요약해줘", "한국어로 번역해줘", "쉽게 설명해줘"와 "직접 입력"
   - ChatGPT로 열기, Claude로 열기
5. **다크 모드 토글**: 헤더 오른쪽

## 수용 기준

### 입력

- URL을 입력하고 변환 버튼을 누르거나 Enter를 누르면 변환이 시작됩니다.
- 입력창에 글자가 있을 때만 지우기 버튼이 보입니다. 누르면 입력값, 결과, 오류, 프롬프트 선택이 모두 사라지고 처음 화면으로 돌아가며, 입력창에 포커스가 갑니다.
- 처음 화면에는 "변환한 본문이 여기에 표시됩니다." 빈 상태가 보입니다.
- `http://` 또는 `https://`로 시작하는 웹 주소가 아니면 변환하지 않습니다. 입력창이 오류 표시로 바뀌고 그 아래에 "http:// 또는 https://로 시작하는 웹 페이지 주소를 입력해 주세요."가 나옵니다. 입력을 고치기 시작하면 이 안내는 사라집니다.

### 변환

- 변환 중에는 "페이지를 가져와 본문을 추출하는 중…" 문구와 스켈레톤이 보이고, 변환 버튼은 비활성화됩니다.
- 본문은 defuddle로 추출합니다.
- 페이지를 가져오지 못하면(없는 주소, 응답 오류, 로그인이 필요한 페이지 등) "페이지를 가져오지 못했어요" 경고와 안내 문구가 나옵니다.
- 페이지는 열렸지만 추출된 본문이 비어 있으면 "본문을 찾지 못했어요" 경고와 안내 문구가 나옵니다.
- 오류가 난 뒤에도 URL을 고쳐 다시 변환할 수 있습니다.

### 결과 확인

- 헤더에 사이트명, URL(원문 링크, 새 탭), 본문 글자 수, 제목, 저자가 나옵니다. 저자가 없으면 저자 줄을 숨깁니다. 사이트명이 없으면 도메인을 대신 보여 줍니다.
- 본문은 Markdown을 렌더링해 보여 줍니다. 제목, 문단, 목록, 인용, 링크, 굵게·기울임, 인라인 코드, 코드 블록, 구분선이 서식대로 보입니다.

### 내보내기

- 내보내기 바는 결과 카드 맨 아래에 붙어 있고, 본문을 스크롤하는 동안 화면 아래에 고정되어 항상 보입니다. 넓은 화면과 휴대폰 폭(375px) 모두 같습니다.
- 바 구성(왼쪽부터): "프롬프트: {현재 선택} ▾" 버튼, 복사 아이콘 버튼, 다운로드 아이콘 버튼, "ChatGPT로 열기", "Claude로 열기". 아이콘 버튼에는 접근 가능한 이름("복사하기", ".md 다운로드")과 툴팁이 있습니다.
- **복사하기**: 복사할 문서(아래 "복사·다운로드 내용")를 클립보드에 넣고, 아이콘이 잠깐 체크로 바뀌며 "Markdown을 클립보드에 복사했어요" 토스트가 뜹니다.
- **.md 다운로드**: 같은 내용을 `{제목}.md` 파일로 내려받습니다. 파일 이름에 쓸 수 없는 문자는 뺍니다.
- **프롬프트 선택**
  - 기본값은 선택 없음이고, 바에는 "프롬프트: 없음"으로 보입니다.
  - "프롬프트" 버튼을 누르면 바 위로 칩 네 개가 펼쳐지고, 다시 누르면 접힙니다.
  - 칩은 하나만 고를 수 있습니다. 고른 칩을 다시 누르면 선택이 풀립니다.
  - 고른 프롬프트가 바에 "프롬프트: 요약해줘"처럼 표시됩니다.
  - "직접 입력"을 고르면 텍스트 입력창이 나타나고 포커스가 갑니다. 바에는 입력한 문구가 표시되고, 비어 있으면 "직접 입력"으로 표시됩니다.
  - 직접 입력한 문구는 저장하지 않습니다. 새로고침하거나, 지우기를 누르거나, 새 URL을 변환하면 사라집니다.
- **ChatGPT로 열기 / Claude로 열기**
  - 넘길 내용은 프롬프트(선택했을 때) + 빈 줄 + 복사할 문서입니다. 프롬프트를 고르지 않았거나 직접 입력이 비어 있으면 문서만 넘깁니다.
  - 넘길 내용이 기준 길이 이하이면 해당 서비스의 새 채팅을 새 탭으로 열면서 입력창에 내용을 채워 둡니다(ChatGPT: `https://chatgpt.com/?q=…`, Claude: `https://claude.ai/new?q=…`). "{서비스}를 새 탭에서 열었어요" 토스트가 뜹니다.
  - 기준 길이를 넘으면 넘길 내용 전체를 클립보드에 복사하고, 해당 서비스의 빈 새 채팅을 새 탭으로 엽니다. "본문이 길어서 클립보드에 복사했어요" 토스트와 함께 "새 탭의 {서비스} 입력창에 붙여넣어(Ctrl+V) 주세요."라는 안내가 뜹니다. 프롬프트를 골랐다면 "프롬프트도 맨 앞에 함께 들어 있어요"를 덧붙입니다.
  - 어느 쪽이든 본문이 잘리지 않습니다.
  - 기준 길이는 interim 값입니다. 아래 "보류한 결정"을 따릅니다.

### 복사·다운로드 내용

- `# {제목}`, 빈 줄, `출처: {URL}`, 빈 줄, 본문 Markdown 순서입니다.

### 다크 모드

- 헤더의 토글로 밝은 테마와 어두운 테마를 오갑니다. 아이콘과 접근 가능한 이름이 현재 상태에 맞게 바뀝니다("다크 모드로 전환" / "라이트 모드로 전환").
- 모든 상태(빈 화면, 로딩, 결과, 오류, 토스트)가 두 테마에서 프로토타입과 같은 모습으로 보입니다.

### 시각 스타일과 반응형

- 화면은 [prototype.html](prototype.html)과 [visual-direction](../../decisions/visual-direction.md)을 따릅니다.
- 휴대폰 폭(375px)에서 가로 스크롤이 생기지 않습니다. 입력창과 변환 버튼은 세로로 쌓입니다.

## 정해진 제약과 이유

- **defuddle 필수**: 사용자가 요구한 추출 라이브러리입니다. 0.19.6에서 Node와 `linkedom` 조합으로 실제 페이지 세 곳(개인 블로그, 한국어 위키백과, React 블로그)을 변환해 제목·저자·사이트명과 Markdown 본문이 나오는 것을 확인했습니다. `defuddle/node` 진입점은 DOM 구현(`linkedom`이나 `jsdom`)을 함께 받아야 합니다.
- **페이지는 서버에서 가져옵니다**: 브라우저에서 다른 사이트의 HTML을 직접 가져오면 CORS에 막히므로, 사용자가 넣은 URL은 서버가 가져와 변환합니다.
- **긴 내용은 클립보드로 넘깁니다**: 일반 기사도 Markdown으로 3만 자 안팎(위키백과 문서 30,237자, React 블로그 30,967자)이라 URL 파라미터에 다 담을 수 없습니다. 사용자가 "짧으면 URL로 채우고, 길면 클립보드로 복사한 뒤 새 채팅을 연다"를 골랐습니다. 자르는 방식은 LLM이 글의 일부만 보게 되어 고르지 않았고, 항상 클립보드로 넘기는 방식은 짧은 글에서도 붙여넣기를 한 번 더 해야 해서 고르지 않았습니다.
- **내보내기는 하단 고정 바**: 본문 위 패널, 하단 고정 바, 오른쪽 고정 패널 세 안을 비교한 뒤 사용자가 하단 고정 바를 골랐습니다. 긴 글을 읽는 도중에도, 휴대폰에서도 내보내기를 바로 쓸 수 있습니다.
- **시각 방향**: [visual-direction](../../decisions/visual-direction.md)을 따릅니다.
- **새 의존성**: [dependency-versions](../../decisions/dependency-versions.md)에 따라 caret 범위로 추가합니다.

## 가정 (바꿀 수 있음)

에이전트가 고른 기본값입니다. 바꾸고 싶으면 바꿔도 됩니다.

- 서비스 이름과 로고는 "feedme"와 "md" 마크로 둡니다.
- 다크 모드의 처음 값은 운영체제 설정을 따르고, 사용자가 토글로 고른 값은 브라우저에 기억합니다.
- 변환 기록은 저장하지 않습니다.
- URL 입력창 아래에 예시 링크 세 개(stephango.com/file-over-app, ko.wikipedia.org/wiki/마크다운, react.dev/blog/2024/12/05/react-19)를 항상 보여 줍니다. 누르면 주소창에 그 URL이 채워지고 입력창에 포커스가 가며, 변환은 사용자가 직접 시작합니다.
- 궁서·굴림이 없는 기기(macOS, 휴대폰)에서는 기본 글꼴로 대체됩니다. 웹 글꼴을 넣지 않습니다.

## 손대지 않는 것

- 로그인, 사용자 계정, 변환 기록 저장: 요구에 없고 1회용 도구로 충분합니다.
- 로그인이 필요한 페이지나 스크립트로만 그려지는 페이지의 본문 추출: 서버에서 브라우저를 띄워 렌더링하는 일이라 범위가 크게 늘어납니다. 이런 페이지는 오류 상태로 안내합니다.
- defuddle의 유료 호스팅 API(`defuddle.md`): 라이브러리를 직접 씁니다.
- 프롬프트 프리셋 편집과 직접 입력한 프롬프트 저장: 사용자가 1회용으로 정했습니다.
- 보노보노 캐릭터 그림: 저작권이 있는 캐릭터라 넣지 않습니다.
- 배포: 이 spec은 앱의 동작까지만 다룹니다. 배포 대상과 방법은 구현이 끝난 뒤 따로 정합니다.

## 보류한 결정

- **URL로 채워 열 수 있는 기준 길이**: ChatGPT와 Claude가 `?q=` 파라미터를 몇 자까지 받는지 shaping 중에는 확인하지 못했습니다(이 환경에서 두 사이트로 나가는 요청이 막혔습니다). interim 기준은 "프롬프트 + 문서가 6,000자 이하"입니다. 구현 중에 실제 로그인된 브라우저로 두 서비스의 새 채팅에 긴 `?q=` URL을 열어 본 결과가 나오면, 그 결과로 기준을 다시 정합니다. 서비스마다 다른 기준을 둘 수도 있습니다.

## 남은 위험

- ChatGPT·Claude가 `?q=` 미리 채우기를 바꾸거나 없애면, 짧은 내용도 채워지지 않은 빈 채팅이 열립니다. 이때는 클립보드 방식으로 바꿔야 합니다.
- 서버가 임의의 URL을 가져오므로 내부망 주소 요청 같은 악용 가능성이 있습니다. 스펙이 요구하지 않은 보안 하드닝은 이번 범위 밖이며, 배포 전에 다시 볼 일입니다.
- defuddle이 사이트 구조에 따라 본문을 잘못 고르거나 일부를 빠뜨릴 수 있습니다. 추출 품질은 라이브러리에 맡깁니다.
- 일부 사이트는 서버에서 오는 요청을 막거나 봇 확인 페이지를 돌려줍니다. 이때는 "페이지를 가져오지 못했어요" 또는 "본문을 찾지 못했어요"로 안내됩니다.
- 장식이 많은 스타일이라 대비가 부족한 곳이 생길 수 있습니다. 본문과 조작 요소의 가독성은 [visual-direction](../../decisions/visual-direction.md)의 경계를 따릅니다.
