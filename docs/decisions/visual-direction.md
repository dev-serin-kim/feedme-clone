# 시각 방향: 보노보노 PPT풍

## Decisions

- 서비스 전체의 시각 방향은 "처음 만든 PPT" 밈(보노보노 PPT) 스타일로 합니다. 무지개 그라데이션 배경, 궁서체 무지개 WordArt 제목, 굴림체 본문, 입체(outset/inset) 테두리 버튼, 노란 박스 소제목, 빨강·노랑 강조, 사선 줄무늬 바처럼 과장되고 촌스러운 장식이 의도된 결과입니다.
- 다크 모드도 같은 스타일을 유지합니다. 배경은 남색·보라색 밤하늘 그라데이션으로 바꾸고, 강조색은 노랑·하늘색 계열로 옮깁니다.
- 승인된 기준 화면은 `docs/specs/url-to-markdown/prototype.html`입니다. 색 값, 글꼴, 장식의 구체적인 모양은 이 프로토타입을 따릅니다.
- 이 스타일은 `ui-composition`의 방식대로 구현합니다. 색은 semantic token 값으로 바꾸고, WordArt 제목·입체 버튼·줄무늬 바 같은 장식은 공통 variant나 project component로 올려서 화면마다 따로 덧씌우지 않습니다. shadcn 컴포넌트 구성은 그대로 씁니다.

## Boundaries

- 보노보노 캐릭터 그림이나 원작의 이미지·로고는 쓰지 않습니다. 저작권이 있는 캐릭터이므로 PPT 밈의 분위기만 가져옵니다.
- 읽기와 조작을 망가뜨리는 장식은 허용하지 않습니다. 본문 영역은 밝은(다크 모드에서는 어두운) 단색 배경 위에 두고, 버튼과 입력창의 포커스 표시와 대비는 유지합니다.
- 배치, 정보 위계, 상태 설계는 이 결정이 아니라 `ui-composition`과 각 spec이 정합니다.

## Why

사용자가 미니멀 무채색(현재 템플릿 기본값), 에디토리얼 읽기(미색 종이 배경, 명조), 보노보노 PPT풍 세 안을 같은 화면에서 비교한 뒤 보노보노 PPT풍을 "아주 마음에 든다"며 골랐습니다. 장식이 많고 일부러 촌스러운 디자인이라, 이유를 모르는 사람은 "정리"하거나 일반적인 미니멀 스타일로 되돌리기 쉽습니다. 그렇게 고치는 것은 이 결정을 뒤집는 일입니다.

## Reconsider when

- 사용자가 시각 방향을 바꾸자고 명시적으로 요청할 때
- 장식 때문에 핵심 흐름(URL 입력, 결과 읽기, 내보내기)을 쓰기 어렵다는 반복 가능한 근거가 생길 때

## Still-rejected alternatives

- 미니멀 무채색(shadcn 기본 토큰 그대로) — 깔끔하지만 사용자가 원한 개성이 없습니다.
- 에디토리얼 읽기(미색 종이, 테라코타 강조, 명조 본문) — 긴 글을 읽기는 편하지만 사용자가 고르지 않았습니다.

## Evidence worth preserving

- 궁서·굴림은 Windows 기본 글꼴입니다. macOS와 휴대폰에서는 대체 글꼴로 보이므로 웹 글꼴을 넣을지는 구현 시점에 판단합니다.
